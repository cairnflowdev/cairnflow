# AGENTS.md — rules for working on cairnflow

Cairnflow is a **diskless** durable execution engine: state lives on object storage through a
SlateDB fork (`vendor/slatedb`), nodes hold no state, write ownership is a lease + CAS, partition
key ranges can split and merge, and each node has one shared WAL. These rules apply to every
contributor, human or AI agent; much of the work happens in parallel git worktrees. Read this file
before changing anything.

Language: **English** for code (identifiers, test names, literals), comments, docs that ship
with the source, and commit messages. Runtime text users see (HTTP error bodies,
`cairnflow --help`, `cairn`/`cairn-ctl`, metric HELP, SDK) is English and quoted verbatim by the
public docs. Internal documents (plans, results, reviews: the `internal` class of
`scripts/oss/manifest.toml`) are not part of the published source; exported files never cite them
or their step, question or lane codes. Check 12 of `scripts/lint-sources.sh` enforces this.

## 1. Non-negotiable rules

1. **Every behaviour change is a pair of commits.** First `test:` — a test that fails on the old
   code, marked `#[ignore = "red until X"]` so the tree stays green. Then `fix:` — remove the
   `ignore`, the test passes. New infrastructure that does not change behaviour (a feature off by
   default, docs) is one `feat:`/`docs:` commit with its tests.
2. **Do not bump `DATA_FORMAT`.** Format 10 is frozen (D27; 9 → 10 was a one-time break made for
   the query layer). Every change to the bucket layout goes through the migration framework
   (`crates/cairn-store/src/migrate.rs`): changing the layout of an existing object is a
   `MIGRATIONS` step. Adding a **new object that is read leniently, where absence means the
   default** (precedent: `range-windows`) needs no step, only an `OBJECT_POLICIES` line
   (`crates/cairn-store/src/format.rs`; the cluster tests fail when an object is written without
   a line). Strictly read objects (`rules`, `catalog/<tenant>`, `range-windows`, `auth/keys`)
   change their header when their layout changes.
3. **No network calls while holding the engine** (D16). All network I/O goes through
   `Lease::released`. It is a compile error; do not look for a way around it.
4. **Ack only after `await_durable`** (D11, INV-5). Every externally visible effect requires
   `Committed`.
5. **Delete only what you can prove.** Wherever the situation is ambiguous (a failed read, a
   mismatched prefix, a Db that has no manifest yet), GC chooses to **keep**. A leak only costs
   space; a wrong delete loses customer data.
6. **An accepted design is a contract.** If the implementation deviates from an accepted RFC
   (`rfcs/`), record the deviation in that RFC's "Deviations from the accepted version" section in
   the same commit; do not silently do something else.
7. **An ambiguous CAS/`Create` result is resolved by reading back.** object_store retries 5xx on
   its own, conditional PUTs included, so `Precondition`/`AlreadyExists` may be our own write, and
   `Err` may have written. Conditional writes go through `cas::put_resolving` (read back, compare
   with the content we meant to write): never treat `Precondition` as a loss, never treat `Err` as
   not written. The content must be unique enough for the comparison to mean something (session +
   term, a freshly issued id); if two writers could write identical bytes, the caller must prevent
   that. Read-modify-write of an object that a single process also writes on `--data-dir` uses
   `cas::put_resolving_or_overwrite`. **Deliberate exceptions:** SlateDB's WAL/manifest, and the
   shared WAL log on a store declared `atomic_put = false` — there `AlreadyExists` is a fence
   (NW-2) and the node fail-stops instead of reading back. The shared WAL log on an `atomic_put`
   store (default for `s3://`, `memory://`, `file://`) reads back and compares every byte
   (`Stripe::resolve`). The `check.sh` row "ambiguous once per op"
   (`CAIRNFLOW_TEST_FAULTS=each-once`, and `each-once+nodewal` for the shared WAL log too) runs
   the cluster tests under ambiguity.

## 4. Report contract

The final message of every work session (an agent's turn, or the description of a pull request)
must contain:

1. **Files changed**, and the commits (hash + title).
2. **Profile run:** WIP or Ready.
3. **The exact commands** run, with their results (PASS/FAIL; on FAIL paste the relevant
   output).
4. **What was *not* checked**, such as skipped e2e rows, chaos not run, or platforms not tried.

## 5. Known traps

- **TS e2e results depend on test order** (the HTTP id counter). A run filtered with
  `--test-name-pattern` is not a baseline.
- **`node --test` needs `--test-timeout`.** The default is infinite, so a hung test looks
  "stuck".
- **Parallel worktrees can kill each other's `node --test`/`cairnflow`** (exit 144). If that
  happens, rerun; do not investigate it as a real bug.
- **Chaos runs on SeaweedFS** (`localhost:18333`, `scripts/dev-store/up.sh`), not MinIO.
  Local MinIO (erasure coding) tears a lease object in two when the client is `kill -9`ed in the
  middle of a CAS (`docs/self-hosting.md` §3), so chaos on it measures the store's bugs, not
  cairn's.
- **`CAIRNFLOW_E2E_NODES=2` must run `e2e.test.ts` alone.** The e2e, durability and
  journal-parity files run in parallel and share the S3 bucket in `CAIRNFLOW_E2E_ARGS`, so
  deployments leak into each other (dozens of 502s). The idempotency-key test (two calls with the
  same `idempotency_key` run one invocation) is flaky in two-node mode (a follower reads the
  journal late); this bug predates the trap.
- **A fresh worktree has no `vendor/slatedb`.** Run
  `git -c protocol.file.allow=always submodule update --init` (`check.sh` does it itself).
- **The `fail` registry is global.** Tests that use failpoints live only in
  `tests/failpoints.rs` (`required-features = ["failpoints"]`) and start with
  `StepController::new()`. Tests that use `pause_at` must run on the `multi_thread` runtime.
- **Tests must pass under both ways of running.** `check.sh` uses nextest (one process per test,
  all binaries at once); `cargo test` (the tests of one binary share a process, binaries run one
  after another) is the fallback and is the WIP command of section 2. Nextest does not run
  doctests — `cargo nextest run` alone does not replace `cargo test`.
- **Do not put a failpoint inside a region that holds the engine mutex**, unless that is exactly
  what is under test. A blocking callback there stops every turn of the range.
- **Do not run `--ignored`/`--include-ignored` on the whole `format_fixture` file** with
  `CAIRNFLOW_REGENERATE_FIXTURES=1` set. The two sample-bucket generators are `#[ignore]` tests
  that write only when that variable is set; if you overwrite them, restore with
  `git checkout -- crates/cairn-server/tests/fixtures`.
- **Conformance traces are written only when an environment variable is set.**
  `regenerate_traces` in `cairn-runtime/tests/conformance_gen.rs` is `#[ignore]` and writes only
  with `CAIRNFLOW_REGENERATE_CONFORMANCE=1`; if written by mistake, `git checkout --
  conformance/traces`.
- **`git stash` is shared between worktrees.** Never use a bare `stash`/`pop`; use a WIP commit.
- **Cluster tests run `verify` on cleanup.** A new cluster test builds its bucket with
  `common::bucket()` (or `cluster_nodes`), not `Arc::new(InMemory::new())`: the `Drop` of
  `Bucket` runs `cairn-ctl verify` after the nodes have dropped, and fails on a finding **that no
  round heals** (`heals == None`). A test that deliberately leaves garbage calls
  `bucket.allow(check, reason)`. When a test returns `Err` and verify also fails, verify's panic
  hides the original error — `CAIRNFLOW_TEST_VERIFY=0` shows the original error; `=all` treats
  every finding as an error (leak hunting).

## 6. Race tests, failpoints and hot paths

Inspired by TiKV's contributor rules (`AGENTS.md`) and its failpoint test cases
(`tests/failpoints/cases/`).

1. **Failpoints in a multi-node harness must be conditioned on the node**, unless the test
   deliberately wants every node. The harness runs every node in **one** process and the `fail`
   registry is global, so an unconditioned point fires on every node. Use
   `StepController::fail_on(&[node], …)` / `pause_at_on`, or the form `failpoint!(name, cond, e)`
   at the site. The current node is set on the engine thread, the node's HTTP handlers and the
   session loop; other background tasks (shared WAL) do not know their node yet — see
   `cairn_store::failpoint`.
2. **Every race test starts with a doc comment describing the interleaving** it reproduces:
   numbered steps, who does what, which gap the test wedges itself into, then "Must see: …".
   Example: `tests/net_partition.rs`.
3. **Callbacks plus channels, not `sleep`.** Wait for an event with `Paused::expect_stopped`,
   `FailGuard::callback` sending into a channel, `Net::wait_held`/`wait_dropped`, or `watch` —
   always with a time limit. `sleep` is only a polling tick inside a bounded loop, never a
   "surely it is done by now".
4. **"Must never happen" paths have a tripwire.** Committing to a range whose lease is no longer
   held, acking before durability, deleting something still referenced: put a failpoint right on
   that branch so a test can turn on `panic` as a tripwire, with its name in `failpoint::NAMES`.

5. **Every I/O `.await` in a background loop is bounded.** Retries go through
   `cairn_store::retry::run` (classifies transient/permanent/ambiguous — ambiguous returns at once
   for rule 7, backs off with `pace::Backoff`, caps attempts and/or time, cancels on stop/lease
   loss); do not write your own `loop { … sleep … }`; a single bounded wait goes through
   `retry::deadline`. Every call site names an `Op` in `retry::ops` (metrics
   `cairnflow_retry_*_total{op}`). SlateDB operations that retry **forever** (`Admin`: reading the
   manifest, WAL references, checkpoints, `set_wal_name`; flushing the memtable; clone) must not
   be `.await`ed directly: use `config::admin_io` or `retry::deadline` — `scripts/lint-sources.sh`
   (check 3) catches it, frozen list `scripts/lint-unbounded.allow`. Direct object_store calls are
   already bounded by the S3 client (`S3_CLIENT_RETRY_TIMEOUT` 30 s + 30 s per request); a path
   that needs a shorter bound (lease/session < TTL) sets its own `deadline` at the call site.

**Hot paths.** Files that start with the line `// #[hot-path]` (every file of
`cairn-server/src/turn/` and `cairn-server/src/flow/`, every file of `cairn-store/src/writer/`,
`nodewal/stripe.rs`) are on the path of every turn. In those files:

- no logging at `info` or above on the normal path of a turn (`debug`/`trace` are fine; rare
  events triggered by an operator, such as capturing a run, may log at `info` with a one-line
  comment);
- no global locks (a mutex/rwlock shared by the whole node or process);
- no synchronous I/O (files, network, `block_on`).

While holding the engine (every `Lease` region, not only marked files): no Db scan that is
unbounded in history. The reader's unbounded scan API carries the `_unbounded` suffix; calling it
in `cairn-server/src/{turn,actor,flow}/` or `cairn-engine/src/engine/` is a FAIL in
`scripts/lint-sources.sh` (check 11) except for the list `scripts/lint-scan.allow` (one reason per
line: what the cost scales with). An O(history) scan goes in bounded chunks and releases the
engine between two chunks (`invocation_tags_after`, `Engine::runnable_chunk`).

Child files of a hot-path file (`X/` under a marked `X.rs` or `X/mod.rs`) must carry the mark on
line 1 too — `scripts/lint-sources.sh` checks it.

Adding a violation requires a reason written at the site; reviewers check against
`docs/guides/flow.md` §4.

## 7. Per-subsystem documentation

`docs/guides/<subsystem>.md` is the map of each subsystem: `lease-session`, `split-merge`,
`nodewal`, `flow`, `query`. Every guide has five fixed sections — invariants (each invariant
points to a test), files to read in order, impact matrix, review checklist, common failure modes.
**Changing an invariant means updating the guide in the same commit**, even when only the test
that proves it changes. Read the guide of the subsystem you are about to change before changing
it.

Design decisions and invariant codes are in `docs/design/decisions.md`; the test layers are
described in `docs/testing.md`. Larger changes (wire protocol, on-bucket format, delete paths,
invariants) start as an RFC in `rfcs/`.
