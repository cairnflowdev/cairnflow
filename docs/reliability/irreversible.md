# Inventory of irreversible decisions

**Status:** an inventory taken by reading the code (no tests were run for it). The `file:line`
references are from the commit the inventory was taken at and drift as the code moves; function names
are the stable anchors. Since then rows X1–X3, X6–X7 (`delete_owner`) and X10 (`LogStore::delete_all`)
**move objects into the trash** (`crates/cairn-store/src/trash.rs`, SM-16, NW-12) instead of deleting
them, so their line numbers moved too. Frames below the floor (`gc_log`) and checkpoints removed from
ancestors are still really deleted — only bucket versioning covers them.

Every conclusion is a **hypothesis drawn from reading the code**, to be checked against the code.
Abbreviations used in the tables:

- **Durable** = read from the bucket right before deciding (GET/LIST/CAS). **Cached** = a copy in RAM,
  a cache, or an inference from history. **Gap** = the time between reading the durable copy and
  acting.
- **Keep** = an unreadable or ambiguous read means doing nothing (AGENTS.md rule 5: delete only what
  can be proven). **Go** = carry on anyway.
- Row codes: **X** deleting a cairn object, **L** a logical delete inside a DB, **S** a SlateDB delete
  that cairn triggers, **M** advancing a floor/mark, **O** opening a DB for writing, **A** an external
  acknowledgement, **R** retiring a range, a table CAS. Elsewhere these rows are cited as
  "irreversible.md X8" etc.

### Suspicions, by consequence

**Data loss (the cluster's customer data):**

- **O1 — the last fence before opening a DB is an inference.** Between reading the fresh table
  (`node.rs:1750`) and `PartitionWriter::open` (`:1860`) nothing on **the DB itself** forbids opening
  it. Safety rests on the chain "a commit needs quiescing, quiescing needs the source lease, the lease
  is ours". No concrete interleaving could be built on the current code (tried: a coordinator on
  another node CASes an intent after we read the table ⇒ its quiesce meets `NotLeader`; gathering the
  ranges of a merge ⇒ `resign` makes us seal cleanly first). Only a suspicion: any new path that opens
  a DB and forgets one of the three checks (fresh table, SM-13, tombstone) recreates RD1/RD2.
- **X1 — D-d leaves in-flight children out of the live set.** `plan` takes `live =
  cluster.partitions()`; a child already cloned (promised by `promised()`) does not get its
  `external_dbs` read. Correct only if the intent's source does not compact/detach between the clone
  and the commit. SM-13 closes the known path (a coordinator loses the lease and takes it back), and
  SlateDB's GC/compaction only run in the process that has the DB open (G5, pinned in 0.3). The
  scenario if the assumption breaks: source P (standing on a retired ancestor Q) is reopened after the
  clone, compacts and detaches Q; the D-d round sees nobody referencing Q (child C is not in the table
  yet) and deletes Q; C commits and lacks SSTs. No current path is known ⇒ a suspicion. A cheap net:
  also read the `external_dbs` of the ids in `promised()` that have a DB.
- **M2 — cutting WAL segments by SlateDB's in-memory mark** (`acquire.rs:120`). The same class as
  NW-7: `apply_uploaded_state` changes the mark in RAM **before** writing the manifest. It was safe
  because `flush_through` only returns once the manifest is durable (`resolve_pending_flushes` runs
  after `write_manifest_update`) and the DB was not handed to the engine yet, so no concurrent flush
  could happen. The interleaving if that broke (a background flush already did
  `apply_uploaded_state` but has not written the manifest): the RAM mark passes the stored mark ⇒ the
  owner-record CAS drops the old log's segments ⇒ the node dies ⇒ the next taker only replays our log
  from `first`, the acknowledged rows of the old log between the stored mark and `max_seen` are lost;
  no record lists the old log any more, so X10 forgets it for good. **Closed:** `acquire` cuts
  segments by `proof::DurableReplayMark` (the stored manifest), and `prune_wal_segments` requires
  that type.
- **X6 — `LiveRefs` keeps the reference set across several rounds** with the same table version
  (`gc.rs:712`), relying on "at a fixed version a live range's `external_dbs` only shrinks". The
  argument holds (a live range's DB is created once, before it enters the table), but it had no
  pinning test; if wrong, it would clean up a DB a live range stands on. **Pinned:**
  `range_clone.rs::n4_live_refs_only_shrink_at_a_fixed_version` — over a fixed set of live ranges,
  each read is a subset of the previous one through compaction + detach. D-d (`proof::RoundRefs`) now
  relies on this argument too: one set per table version for every proof of a round.
- **X2/X10 — deleting by prefix LIST.** `delete_range_objects` (`ranges/<id>`) and
  `LogStore::delete_all` (`nodewal/<node>/<inc>/<stripe>`) are correct only because object_store's
  `list` matches **by path segment** (`ranges/1` is not a prefix of `ranges/10/…`). A store or store
  wrapper matching raw strings would make D-d of range 1 delete ranges 10–19, and the sweep of
  incarnation 1's log delete the logs of incarnations 10–19. object_store 0.14.2 states this contract
  (`lib.rs:1257`) and InMemory follows it (`memory.rs:325`). Pinned for `memory://`, `file://` and
  `FaultyStore` in `library_contracts.rs::o5_list_matches_whole_path_segments`; real S3 not yet (OS5
  in 0.3).

**Data loss outside the cluster (forks/backups):**

- **X12:** an expired barrier is deleted with a bare DELETE after a GET; a renewal landing in the gap
  is lost; the deadline is compared across two machines' clocks. **Narrowed:** only barriers expired
  for more than `BARRIER_REAP_GRACE` (1 hour) are deleted — the gap only remains with clock skew of
  more than an hour (`gc.rs::barrier_reap_spares_a_barrier_that_just_expired`).
- **X13/O4:** a `fork`'s barrier is valid for 24 h and nobody renews it automatically (the user must
  run the printed command). Past that, the source cluster's D-d deletes ancestors the copy stands on.
  By design, but recovering from a fork depends on it. Add S5: a fork clone taking > 1 h.

**Leaks:**

- **X10:** a tombstone written by SM-11/`retire_alone`/`force-retire` copied the dead owner's
  `wal_segments` ⇒ that log was never forgotten by X10 (seal + floor, a few objects each time).
  **Fixed:** a tombstone written on behalf drops `wal_segments` (`gc::tomb_segments`). A tombstone
  written by the keeper itself (`LeaseKeeper::retire`, a dirty retirement) still keeps its segments —
  not changed yet.
- The seal and the `forgotten` mark of each forgotten dead log (2 objects, forever — the price of the
  fix the M3 model found).

**Other:**

- **X7:** `delete_owner` is a bare DELETE without a tripwire; the SM-14 condition is only held by the
  callers.
- **X14:** deleting a deployment: a new invocation pinning it between the count and the DELETE (an
  operator path).
- **A1:** `Committed: Copy`.
- Missing tripwires on three "never" branches: D-d deleting a DB that is still referenced (X1), floor
  GC deleting an object holding frames the stored manifest does not cover (X8), the sweep sealing a
  live session's log (X9).
- L1 lacks a test "broken archive ⇒ no delete".
